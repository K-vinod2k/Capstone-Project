# Topic 3: Persona Engine, LLM & RAG Retrieval

**What this section covers:** How the system understands user intent, selects a hero, and retrieves the right motion.

---

## Section A — The Persona Brain

**Q1. What model powers the persona engine, and why was it chosen over a smaller model?**
> Qwen2.5-72B via HuggingFace Inference API. Chosen for strong instruction-following, ability to maintain character voice across a conversation, and multilingual capability. A smaller model (7B-13B) would struggle to reliably match vague prompts to specific heroes while simultaneously generating in-character spoken replies.

**Q2. What is SCoT (Structured Chain-of-Thought)? How does it help the robot give better responses?**
> SCoT makes the model output `internal_reasoning` before producing the final answer. The model "thinks out loud" about which hero matches the prompt and why, then generates the reply and gesture description. This reduces hallucinations — the model is less likely to match "thunder" to the wrong hero if it reasons through it first.

**Q3. What does persona_brain.py return? List the three outputs and explain each.**
> 1. `spoken_reply` — the hero's in-character quote to be displayed/spoken (e.g., "HULK SMASH!")
> 2. `gesture_description` — a text description of the motion (e.g., "raises both fists overhead and slams down") used as the RAG query
> 3. `internal_reasoning` — the model's SCoT reasoning, used for debugging and transparency

**Q4. What happens if the HuggingFace token is missing? Does the system crash or degrade gracefully?**
> Falls back to mock mode — hardcoded hero responses from a lookup table. The system continues to function with reduced intelligence: it still retrieves animations and deploys to hardware, but the persona matching is rule-based instead of LLM-powered.

**Q5. How many heroes are in HERO_REGISTRY? Name three and describe what makes each distinct.**
> 9 heroes. Examples:
> - **Hulk** — rage-based, physical smashing, very aggressive poses with both arms
> - **Iron Man** — tech-genius, repulsor blasts, one arm extended forward
> - **Spider-Man** — agile, web-shooting gesture, web-slinging or landing poses

## Section B — RAG Retrieval

**Q6. What is RAG? Why is it better than hardcoding a lookup table for this use case?**
> Retrieval-Augmented Generation — instead of exact keyword matching, it embeds the query into a vector space and finds the semantically nearest stored entry. Better than a lookup table because it handles paraphrases: "smash the ground," "destroy everything," and "Hulk mode" all retrieve the hulk_smash animation even though none say "hulk_smash" exactly.

**Q7. What embedding model does your RAG system use, and what does it embed?**
> `sentence-transformers/all-MiniLM-L6-v2`. It embeds text descriptions of each hero animation (gesture descriptions + hero keywords). At query time, the user's natural language input is embedded with the same model and compared to stored embeddings.

**Q8. What is FAISS, and what problem does it solve compared to a linear search?**
> Facebook AI Similarity Search — a library for fast approximate nearest-neighbor search in high-dimensional vector spaces. With 10 animations it doesn't matter much, but FAISS scales to millions of entries; a linear dot-product search over all entries would be O(N) while FAISS uses index structures to achieve sub-linear retrieval.

**Q9. If a user says "do something powerful," which hero does RAG return and why?**
> Likely Hulk or Thor — "powerful" semantically aligns with "HULK SMASH" and "God of Thunder" descriptions in the RAG dataset. The exact result depends on which embedding has the highest cosine similarity to "do something powerful."

**Q10. What is the RAG dataset? How was it generated, and what does each entry contain?**
> Generated by `generate_rag_dataset.py`. Each entry contains: the animation name, a text description of the motion, hero keywords, and the embedding vector. It's stored as a FAISS index + metadata file (`kim_rag_database`). The descriptions were written to capture both the hero identity and the physical motion.

## Section C — Intent to Motion

**Q11. What is the output of RAG retrieval? A hero name? A file path? An embedding?**
> A tuple of `(pkl_path, score, animation_name)`. For example: `("kim_workspace/movements/hulk_smash_kinematics.pkl", 0.87, "hulk_smash")`. The score is cosine similarity (0-1).

**Q12. How does the system go from "matched: hulk_smash" to actually loading the right PKL file?**
> In `example.py` / `main.py`: `pkl_path = MOVEMENTS / f"{anim}_kinematics.pkl"`. The animation name from RAG is used to construct the path to the pre-validated, velocity-clamped PKL in `kim_workspace/movements/`.

**Q13. Could two different prompts ("smash" vs "hulk") return the same animation? How?**
> Yes — both "smash" and "hulk" have high semantic similarity to the hulk_smash entry's description ("HULK SMASH, raises fists, slams down"). FAISS returns the top-1 nearest neighbor regardless of the specific words used. Both queries land close to the same point in embedding space.
